## 接口（合同级，标准库）

1. `MessageHeader` / `ContractContext` / `EstimatorState`：四级上下文 + clock_id + px4_boot_id + sync_generation + validity。
2. `validate_message(header, context, now_ns, allowed_age_ns, mapping=None) -> reason`：按 §27.2 顺序返回明确错误码，不使用异常代替拒绝。
3. `ActionEnvelope` + `VelocityPayload`：Action Schema v2.0，含 observation_id、input_capture_interval_ns、earliest_input_safe_deadline_ns、issued/expires、axis_validity、digest/identity。
4. `ActionArbiter.admit_new / send_cached / revoke`：严格递增序号、合法重发不续期、乱序/序号复用/缓存回滚拒绝、ADMIT 提交在锁内。
5. `OwnershipState`：PENDING/ACTIVE 交接、交接必须改变 control_epoch、超时分支、PX4 failsafe 后不再发布。
6. `EpochManager`：impact/localization reset/mission reset/PX4 单独重启/Companion 重启的原子失效，含队列清理、GRU 隐状态与 previous action 代际、推理结果拒绝、quarantine 区间。
7. `from_velocity_v1`：显式迁移适配，必须显式提供轴有效性与观测溯源，否则拒绝（不允许只换 schema 标签）。

## 验收方法

- 先写失败测试（RED），记录失败原因对应未实现能力；再实现；`pytest -q` 全绿（含既有 33 条）。

- 明确拒绝项：过期边界 `now >= expires`、重发不延长 TTL、旧 epoch、quarantine、PX4 boot 变化、所有权冲突、partial-axis 默认拒绝。
- 证据：`docs/reports/g2_6/G2_6_CONTRACTS_REPORT.md` + RED/GREEN 日志 + `git rev-parse HEAD`。

## 运行预算与停止条件

- 预算：单次 `pytest -q` < 5s；总实施 < 2h；不启动 Isaac/训练。
- 停止条件：出现非有限值、合同违约、既有 v1 测试回归失败，停止并先诊断再做后续包。

## 失败处理

- 若 v1 测试被破坏：回退 v1 行为，新增测试只针对 v2 新模块。
- 若某条 V2.2 要求无法在纯软件层验证（如固件掩码、PX4 实际响应）：实现拒绝/未验证标记，报告写 NOT RUN，不写成 PASS。
