| 内容 | 当前依据与边界 |

## 2. 已有实机事实与规划前提

用户确认：PX4 固件版本 1.17；无 GPS、有光流、无磁力计；已经实现定高飞行和上位机 MAVLink 通信。

这些事实不自动证明速度 Offboard、稳定水平悬停、跨场定位、精确返库或拦截已经通过。与此同时，用户已明确不以旧项目验证进度阻塞本研究，故无需以重复整理旧通信程序为首项任务。

用户补充过前视视觉、下视相机、IMU、光流和向下测距等信息。这些是可考虑的观测来源；最终传感器数量、型号、安装和网络输入均未冻结。

Windows Isaac Lab 是已知研究环境背景，独立研究工作区为 `E:\isaac\proj_boom_birds`。既有环境检查结论属于此前快照，本次未重新运行仿真、检查依赖或测试训练吞吐；当前环境不等同于任何论文已复现。

## 3. 最新实测反馈：深度计算成本

用户实际测试反馈：即使轻量双目，输出深度对性能的占用仍然很高。测试的具体计算平台、算法、分辨率、帧率、CPU/内存占用、端到端延迟尚未汇总。

据此，机载持续计算稠密双目深度不再作为默认前提。该反馈不能外推为所有双目实现、稀疏测距或专用深度硬件必然不可行；也不能反过来证明单目视觉已能满足任务。

评估必须覆盖采集、解码、预处理、深度/特征生成、策略、目标识别、通信和散热供电。论文中的网络推理毫秒数不是完整链路开销。

## 5. 当前需要的信息及硬件取舍

| 必要信息/任务 | 当前推荐来源 | 选型状态 |
| --- | --- | --- |
| 姿态与短时运动 | 复用飞控 IMU 与 PX4 估计 | 不增设独立 IMU；原始 IMU 是否进策略待消融 |
| 速度控制所需运动估计 | 光流、向下测距等交 PX4 融合 | 优先成熟集成模块；有效高度/纹理范围需验证 |
| 基地、阵营、小装甲 | 前方彩色图像 | 前方视觉是核心需求；单/双目及具体规格未定 |
| 前方障碍与距离线索 | RGB 时序策略作为研究候选；必要时补有限距离观测 | 单目充分性未证明；不默认运行稠密深度 |
| 机库相对位置与朝向 | 下视相机，或由机库几何支持的其他已有视角 | 垂直精确降落时优先下视；未据几何证明永久必装 |
| 近地距离 | 向下测距 | 优先与光流集成；跨台阶时不等于世界坐标高度 |
| 长距离返程方向与重捕获 | 相机看到的基地/机库/场地参照及有限运动估计 | 光流积分、GRU 均不能单独保证；额外定位是否需要待验证 |

光流相机与普通下视相机部分功能重叠，但自行从相机计算光流会增加标定、同步、转动补偿、质量判断和计算成本，不能只按少一块硬件判断收益。旧资料记录 MTF-02P，为光流/测距一体模块候选，不是本轮确认的最终采购项。

PX4 1.17 的速度控制要求有效速度估计；保留飞控不自动提供失效时可靠悬停/返航能力。参见 [Offboard](https://docs.px4.io/v1.17/en/flight_modes/offboard) 与 [光流说明](https://docs.px4.io/v1.17/en/sensor/optical_flow)。

## 6. 当前较合理的架构候选

前视图像 + PX4 融合运动状态 + 必要的高度/质量信息 + 任务条件 → 轻量局部导航策略 → 指令限幅/时效/仲裁 → PX4。

基地与小装甲识别保留目标身份和相对观测输出；机库捕获与降落按需使用下视观测。简单任务状态机组织起飞、去程、目标捕获、任务、返回、机库捕获和降落。一时刻只允许一个技能发运动指令。

策略首版不默认接收两路完整图像、原始 IMU、原始光流及融合状态的全部组合。先复用估计结果，通过消融决定附加输入。颜色识别与远距小目标需保留足够原始图像信息，不能因导航低分辨率就将全部感知统一降分辨率。

这是一套待验证的结构建议，不保证单目可行，不保证无需任何定位，也不要求每个技能均采用 RL。当前速度/偏航率接口为推荐起点，尚未与姿态/角速度接口做同条件比较。

## 7. 已经收敛与尚未收敛的决策

已收敛：PX4 保留；研究独立推进；基础运动与避障先于任务识别；轻量化按全系统计算；传感器逐项论证；基地→小装甲；统一阵营配置；返库必须纳入完整任务；拦截独立评估。

尚未收敛：单目/双目/有限前向测距；最终机载计算平台；下视相机是否能省；是否需额外全场定位；最终策略输入、记忆结构、训练算法；精确质量/功耗预算、速度高度范围和验收门限。

前面“单目作为基础”“双目优先”“全部传感器融合”等表述属于阶段性建议。当前不将这些相互冲突的建议视为全部已接受；仅保留本节明确的状态。

## 8. 下一步最有价值的验证

1. 定义实际运行范围：高度、速度、通道净空、临时障碍、机库可见范围与降落容差。可先采用明确标为假设的范围开展仿真。
2. 整理已做双目测试的计算条件与分项开销，避免重复试验或错误归因；不要求等待现有飞行项目完成。
3. 冻结首个仿真任务：在简化场地完成到点、停止和避障。距离/深度观测作为对照，RGB+融合状态作为部署候选；假设测距的分支单独记录硬件条件。
4. 对候选比较碰撞率、到达率、停止距离、观测到动作延迟、CPU/内存和能量代价。训练环境可用真值计算损失，部署策略不得暗用实机没有的坐标或障碍真值。
5. 独立验证返程重捕获，再确定定位与下视配置。通过后进入真实任务图像采集、基地/装甲及机库技能。

完整硬件选型和训练路线，应由上述最小实验缩小不确定性后再冻结。当前尚未产生这些实验结果。
