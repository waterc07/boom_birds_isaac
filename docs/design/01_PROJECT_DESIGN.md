# v1.2 项目设计与需求追踪

2026-10-11。架构方向已由用户确定；任务性能尚未验证。[总纲](../../PROJECT_PLAN.md)为入口。

## 目标和成功定义

在严格质量/算力限制下，开发可逐步迁移到PX4微型四旋翼的自主移动与比赛任务系统。最小研究闭环是受限场景到点、停止和静态避障；最终主任务闭环包含去程、基地/小装甲捕获、规则允许的任务动作、返程、机库捕获与降落。首版允许限定速度、飞行高度、障碍类别、照明和起始区域，但必须在报告中冻结这些条件。

成功包含算法表现、观测真实性、推理预算、机体预算和可复现性五部分。仿真成功、机载重放成功、真实飞行成功分别统计，不能合并。长期目标不是必须使用某一种RL，而是复用开源成果，在有限范围内获得可解释的工程进展。

## 已知与非目标

已有PX4 1.17、无GPS、光流、无磁力计定高及通信为用户事实。通信可实现是研究前提；不等待旧工程进度。已有Windows Isaac Lab用于研究，不承诺当前已经兼容NavRL旧版本或DiffPhysDrone CUDA扩展。

首版不建设多机协同、完整SLAM/ROS导航栈、任意环境高速穿越、在线实机探索、自研RL优化器或电机策略。拦截是明确的独立研究分支。侦察、库内卸载、充电/能源循环是待确认扩展；若赛季规则将其设为必须，再提升为P7前置要求。

## 架构边界与阶段变化

学习策略负责局部运动，任务状态机负责目标、阶段和阵营，PX4负责估计和内环，监督器负责指令许可与时效。返程方向和目标获取必须有实际来源；GRU不能代替未经验证的全场定位。

P1/P2可显式使用仿真真值建立算法对照。P3开始部署候选只能用真实可获得的观测。训练奖励、critic或teacher可以读取额外信息，但actor导出后不得依赖这些信息。模型接口相同不代表不同传感器可用同一权重。
