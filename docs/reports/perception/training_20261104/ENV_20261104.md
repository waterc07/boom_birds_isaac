## 4. 兼容性诊断记录（ultralytics 8.2.0 × numpy 2.x）

初次安装按「不额外钉版本」解析到 numpy 2.4.6 / opencv-python 5.0.0.93 / pandas 3.1.0 / ml_dtypes 0.6.0。GPU smoke 的前向与 1 epoch 训练（含 loss 反传）均通过，但在**训练内置验证阶段**崩溃：

```text
File "...\ultralytics\utils\metrics.py", line 521, in compute_ap
    ap = np.trapz(np.interp(x, mrec, mpre), x)  # integrate
AttributeError: module 'numpy' has no attribute 'trapz'. Did you mean: 'trace'?
```

诊断：ultralytics 8.2.0（2024-05）调用 `np.trapz`，numpy 2.4 已移除该别名；这不是标签/数据/GPU 故障。处理：在隔离 venv 内把 numpy 钉到 `1.26.4`，并按依赖解析同步降至 `opencv-python 4.10.0.84`、`pandas 2.2.3`、`ml_dtypes 0.5.4`（后三者新版均要求 numpy>=2）。修复后 `pip check` 输出 **No broken requirements found**，GPU smoke 与 1 epoch 训练/验证复跑 PASS。

- 未采用的替代：不猴子补丁 `np.trapz`、不改 ultralytics 源码、不升级 ultralytics（协议钉 8.2.0）。版本组合的失效条件：升级 ultralytics/numpy 任一项都必须重新跑 GPU smoke 与 val 一致性。
- 该组合的「8.2.0 × torch 2.7 × CUDA 12.8 × sm_120」= 本机实测可用（smoke + 训练 + 导出）；不等于 RKNN 板端可用（UNKNOWN）。
