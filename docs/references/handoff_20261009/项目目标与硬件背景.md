# Boom_Birds 机器学习支线：项目目标与硬件背景

整理日期：2026-10-09。供另一台电脑上的 AI 接手独立研究。

## 1. 用户意图与支线边界

原工程继续开发。本任务新开一条 Isaac Lab／机器学习支线，研究同一架微型无人机如何自主完成项目任务。

新支线可以重新设计软件架构、观测、动作空间和算法。无需沿用 OpenVINS、双目匹配算法、EGO-Planner、ROS 2 或现有任务状态机；这些是原路线的实现选择，不是新支线的需求。

现有飞控实物、动力、传感器、机载计算资源和比赛约束仍是研究背景。PX4 是现有固件背景，是否继续使用及如何接入学习策略，由新支线论证。不能因为放弃旧软件而忽略执行器能力、推力饱和、机载算力和失效保护。

新支线在另一台电脑的独立目录／仓库工作。默认只做建模、仿真、训练与离线评估，不修改原工程、不部署树莓派、不刷写飞控、不开展实机飞行。后续整合或实机试验另行安排。

## 2. 项目要完成什么

项目为 RoboMaster 2027 微型空间智能无人机预研。目标是全自动微型四旋翼系统，具备从机库出发、在受限场地中感知与运动、完成任务及返库的能力。

| 能力 | 要完成的行为 | 尚未确定的信息 |
| --- | --- | --- |
| 自主起飞 | 从机库或配置起点起飞，进入可控飞行状态 | 机库结构、释放方式、初始位姿误差 |
| 稳定飞行 | 悬停、移动、转向，受限空间中保持可控 | 允许漂移、速度、加速度、倾角等定量门限 |
| 环境感知与避障 | 利用可上机的传感器识别可通行空间，避开结构与障碍 | 精确地图、材质、光照、最小障碍尺度 |
| 目标检测与跟踪 | 发现任务目标，持续估计目标相对方向／运动 | 目标类别、尺寸、运动分布、训练数据 |
| 侦察 | 到观察位置悬停，采集并保存任务信息 | 所需信息、识别精度、数据格式 |
| 返库与降落 | 返回机库附近，捕获降落区域、对准并落地 | 机库位置、落点容差、标记布局、接地条件 |
| 数据卸载 | 返库后将机载记录交给机库，再提供给雷达等系统 | 有线／近场接口、协议与任务数据格式 |
| 能源与循环 | 判断是否有足够能量完成任务和返库；支持降落—充电—再起飞 | 最终储能、充电接口、热限制、循环次数 |
| 失效处置 | 传感器、估计、计算或控制链路失效时进入可验证的安全状态 | 不同场景的安全动作、许可条件与边界 |

项目还保留直接接触指定装甲目标、主动迎击飞镖／弹丸两类赛事能力方向。官方将其列为“典型功能”，不等于三类能力均已有强制验收条款。目标判定、载荷、接触条件与计分细节仍待明确。新支线先完成通用飞行、感知、导航、返库与循环；这些赛事扩展任务单独定义，不在首个训练环境中混为一个奖励目标。

首个完整任务可采用“起飞 → 到观察点并悬停采集 → 避障返库 → 对准降落 → 数据卸载 → 模拟充电 → 下一轮”。这是研究任务建议，场景尺寸和容差需要配置，不能写成已公布的官方任务规格。

## 3. 当前规则约束

依据本机主工程 `docs/RULE_BASELINE.md`，基线为 2026-09-09 书面前瞻。明确新条款优先，未述项沿用已有旧规范，均未定义者保持 TBD。接手时需确认是否已有后续正式规则；本次没有重新检索赛事规则。

| 项目 | 当前基线 | 对仿真／学习任务的影响 |
| --- | --- | --- |
| 自动运行 | 比赛全自动；机库内可以与机库通信 | 正常任务不能依赖人工连续操纵 |
| 单次飞行 | 旧规范继承：起飞持续时间至多 30 s；计时起止与判罚 TBD | 记录任务时间；显式安排返库和安全时间余量 |
| 悬停 | 持续悬停至少 10 s；漂移／高度容差 TBD | 单独评价悬停，不用动画演示代替稳定性指标 |
| 尺寸与质量 | `150 ≤ m ≤ min(249, 322.5 - 1.225D)`；m 为 g，D 为任意情况下最大包络边 mm | 模型质量和外廓必须配对，不随意使用默认无人机参数 |
| 项目包络 | 当前设计目标 118–120 mm，仍需 CAD 验证 | D=118 mm 时上限约 177.95 g；D=120 mm 时约 175.5 g |
| 结构保护 | 全包围桨保；桨叶和机体不得外露；碰撞时桨叶不得接触装甲模块 | 碰撞判定按完整外廓，不只算质心到障碍的距离 |
| 安全 | 配套紧急停桨遥控器／接收机和安全员 | 失联动作与独立紧急停桨分别验证 |
| 机上机构 | 不允许安装发射机构 | 不为任务自行添加此类硬件 |
| 机库 | 装载上限 4 架，收纳不超过 300×300×200 mm | 可先做单机；上限不代表必须四机 |
| 机库能源 | 总容量上限 300 Wh；内部任意一点对电池负极不超过 30 V | 这是机库约束，不能套为机载能源上限 |
| 侦察通信 | 获取信息后返库回传；库外通信许可和协议 TBD | 机载记录与返库卸载是任务的一部分 |

10 s 悬停与 30 s 单次飞行需同时考虑。现有 30 m／长时间仿真只是研发场景，不能据此认定满足比赛计时。研发可使用更长 episode，但报告必须区分研发任务和规则约束任务。

场地应考虑制高点、隧道、工作台及中央机库区域。精确几何没有提供；不要用自行生成的森林或室内地图冒充正式比赛场地。

## 4. 已有硬件与研究边界

这里区分已购／锁定件、当前验证平台和候选件。训练电脑不是机载电脑。

| 子系统 | 已知背景 | 状态与限制 |
| --- | --- | --- |
| 构型 | 同平面四旋翼，固定前向任务方向，全包围桨保 | 118–120 mm 包络为设计基线；CAD、惯量、重心及整机质量未闭合 |
| 电机 | 4×T-MOTOR 1103 8000KV | 已锁定；不能用型号推导出已实测推力曲线 |
| 桨叶 | 4×Gemfan 2216S-3，2.2 inch 三叶 | 已锁定；柔性与保护合规仍需核验 |
| 开发电池 | 3S 300 mAh、95C、记录质量 23 g、约 19×18×50 mm | 化学体系、满充电压、连接器、内阻及放电曲线待确认 |
| 飞控／电调 | MicoAir743v2-AIO-45A，现有方向运行 PX4；电调协议基线 DShot600 | 已购；实板 revision、准确 target、输出映射及安全动作仍需验证 |
| 飞控惯性传感器 | 厂商资料记录 BMI088＋BMI270 双 IMU | 新支线可使用飞控 IMU；真实噪声、速率、延迟、安装外参待测 |
| 独立光流／测距 | 已购 MTF-02P，直接连接飞控 | 当前安全传感器背景；光流和测距是两种观测，实际融合性能未验收 |
| 机载计算验证平台 | Raspberry Pi 5／Ubuntu 24.04 ARM64 | 当前平台硬件固定；全链实时负载和整机质量／功耗仍未闭合 |
| 当前前向视觉输入 | USB 免驱同帧左右拼接双目，2560×960 MJPEG，每目 1280×960 | 具体型号、快门、安装方向待核验；60 FPS 为采集配置请求，不是算法输出能力 |
| 双目几何候选 | 棋盘估计基线约 67.6718 mm | 是标定结果；独立米制距离验收未完成，仿真先标注候选假设 |
| 当前下视实验相机 | IMX219；已有 1640×1232 内参候选 | 滚动快门；安装外参、距离、新姿态与近地捕获未验收；不替换原 USB 双目 |
| 前视／下视最终相机 | 前视彩色全局快门、下视单色全局快门为历史候选方向 | 不是已购实物规格，不可默认训练时已具备 |
| 补充障碍传感器 | 8×8 多区 ToF 类候选 | 未确定；首版不能假定已安装 |
| 最终储能 | 高概率超级电容＋独立管理模块 | 未定；首轮以当前电池背景研究，不能编造电容参数 |
| 机库与充电 | 收纳、卸载、充电与再起飞为系统目标 | 机械、电气接口与实现方案待定；可先建立抽象事件模型 |

MTF-02P 厂商资料记录：5 V、平均 100 mA、3.3 V LVTTL 串口、115200 baud、50 Hz、约 1.5 g；90% 反射率条件下 ToF 标称 0.02–6 m。这些是现有 BOM 手册摘录，未在本次重新核验，不能直接当成实际场地有效量程。

动力研究曾以约 160 g 为参考点，目标推重比至少 2.5、单电机静推力约 100–120 gf。这些是待实测的设计目标，不是模型已知能力，也不是额外质量上限。

Pi 5、AIO、传感器、线束、电池和保护结构能否一起满足最终质量／电源预算尚未确认。当前验证平台可用于算法实验，但不能当成已完成的参赛整机。

## 5. 给机器学习方案的要求

允许端到端学习、分层策略、模仿学习、强化学习，或学习与传统控制混合。不要因为“机器学习”就默认整条链必须用一个网络替代。

接手 AI 应明确提出并验证以下选择：

- 学习对象：飞行控制、视觉导航、目标跟踪、末段降落、任务决策中的哪一层；其他层由什么承担。
- 观测：真实部署时可获得的图像、IMU、光流、测距、飞控状态、任务状态和能源估计；逐项写频率、时延与缺失处理。
- 动作：任务目标、速度、姿态／推力或更低层命令；选择必须与可实现的硬件接口、更新频率和执行器约束一致。更低层动作会增加控制与安全验证工作，不能视为现成接口。
- 部署：策略推理在机载平台运行；另一台电脑承担 GPU 训练与仿真。先给模型大小、内存、推理时延和传感器处理预算，再做上机结论。
- 训练真值：允许用世界真值计算奖励、评估、教师动作或 privileged critic。部署 actor 的观测必须可在实物上获得，报告中分别列训练输入与部署输入。
- 模型：质量、惯量、重心、臂长、旋翼位置、推力／反扭矩、响应滞后、饱和、阻力和电源变化均配置化。未测参数写 ASSUMED／TBD，给依据与变化范围。
- 随机化：围绕可信误差范围设置动力、传感器、光照、纹理、遮挡、初始条件、时延、丢帧和扰动；不要用任意宽范围掩盖建模缺失。
- 安全：正常任务、传感器失效、越界、能源不足、计算失联和接地完成有独立判据。训练奖励不能替代运行时安全约束。

现有 Pi 感知门限可作为原路线的比较参照：CPU P50/P95≤70%/85%、深度≥15 Hz、消息年龄 P95≤150 ms／最大≤300 ms，另有 1800 s 连续运行与 10 次启停。新支线若不生成深度，不强套深度 FPS；应定义对应的观测到动作时延与实时性门限，并与原路线分开报告。

## 6. 研究推进与交付要求

Isaac Lab 用于机器人学习；涉及图像与物理传感器仿真时同时评估 Isaac Sim。另一个环境先检查官方版本兼容表，再固定所用版本；不要把不同版本教程混用。[Isaac Lab 官方仓库](https://github.com/isaac-sim/IsaacLab)、[Isaac Sim 环境要求](https://docs.isaacsim.omniverse.nvidia.com/latest/installation/requirements.html)。

| 阶段 | 工作 | 本阶段需要交付的证据 |
| --- | --- | --- |
| 环境与设计 | 读取新电脑 GPU／显存、系统、驱动、内存、磁盘；核对兼容性；选择学习层级 | 环境清单、版本锁定、方案与参数缺口表；缺硬件参数时先做显式假设模型 |
| 飞行基础 | 在参数化四旋翼上验证起飞、悬停、目标移动与降落；先有可用参考控制／策略 | 可重复启动命令、固定种子、状态曲线；悬停误差、饱和及失败原因 |
| 首个学习任务 | 选择一个清楚的任务，如目标位置跟踪或平台相对降落 | 观测／动作／奖励／终止定义、训练日志、checkpoint、独立评估 |
| 感知与导航 | 按部署传感器加入图像／IMU／测距，在不同布局中验证避障和目标捕获 | 未见场景表现、完整机体碰撞、时延与失效记录；真值观测实验单列 |
| 完整任务 | 连接起飞、侦察、返库、降落、卸载和抽象充电；后续替换真实能源模型 | 任务状态记录、时间与能量预算、失败收尾、重复任务统计 |
| 迁移准备 | 缩小模型、测机载推理预算，列出真实测量与校准要求 | 模型导出／重载结果、部署接口、测量清单；此阶段不自动操作硬件 |

每个任务记录成功率与分母、完整机体碰撞率、目标／落点误差、完成时间、任务能耗模型、失效原因和策略推理时延。策略比较使用相同环境分布及指标，固定测试集并与训练集分离。训练种子和评估种子分开，多种子结果不能只报最好的一次。

项目没有给出所有误差／成功率门限。接手 AI 可以提出研究门限并标为 PROPOSED，经确认后再固定；不得把提议写成赛事规定或已有验收要求。

结果使用 PASS／FAIL／BLOCKED／NOT RUN，并说明是模型检查、软件测试、仿真、机载推理测试、台架还是实飞。仿真成功不证明真实动力、标定、机体合规或飞行安全。

## 7. 接手时应优先确认的缺失信息

1. 新电脑操作系统、GPU 型号与显存、驱动、RAM、可用磁盘、可安装环境。
2. 首个学习任务及优先级；若用户未指定，先提出一个最小任务并推进环境检查。
3. 已有 CAD、整机质量、惯量、重心、旋翼几何和实测推力／功耗曲线。
4. 机载计算平台的具体配置、可用功率和推理预算。
5. 相机真实内外参、快门、视场、同步、IMU 噪声／时延、测距有效条件。
6. 机库几何、降落区域、板标记、任务目标外观和运动分布。
7. 正式场地图与最新规则、计时／悬停／接触／拦截判据。

缺少参数时可以开始通用四旋翼学习实验，但必须说明模型与实物的差距。不得用默认无人机参数或 GPU 高帧率证明这架微型无人机可完成任务。
