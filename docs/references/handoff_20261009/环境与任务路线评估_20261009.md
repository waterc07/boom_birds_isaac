# Boom_Birds 环境与任务路线评估

日期：2026-10-09。范围：本机环境检查、基础仿真探针、研究路线建议。没有安装或修改依赖，没有修改原工程，没有操作实机。本文件为新增评估记录，不在原 manifest.json 中。

## 1. 结论

现有 Windows 环境可以运行基础 GPU 四旋翼仿真，可作为独立研究的起点。尚不能作为依赖一致、训练已验证的固定实验基线。建议先建立参数化动力学与参考控制器，再研究速度跟踪和定高悬停，随后扩展到视觉导航、平台相对降落和完整循环任务。

主要项目风险是模型与实物不一致、部署观测不可得、机载资源与整机质量预算未闭合，以及任务时间与返库余量，不能由训练电脑性能解决。

## 3. 官方文档对照与环境限制

Isaac Lab v2.3.0 安装文档支持 Windows，Isaac Sim 5.X 使用 Python 3.11；pip 示例使用 Sim 5.1.0、torch 2.7.0 和 torchvision 0.22.0 的 cu128 构建。当前 Python／Sim／Torch 组合与该安装示例一致，但这不证明本机开发提交与所有训练库兼容。

Isaac Sim 5.1 要求页列 RAM 32GB、显存 16GB、Windows 驱动 580.88，RTX 5080 属于 Good 栏。当前驱动较新，基础运行探针已通过，但 Insider 系统与该驱动组合没有完整验证。

官方页面存在版本维护信息差异：Lab v2.3.0 安装页仍推荐 Sim 5.1.0，Sim 5.1 文档顶端已标记不再受支持。建议将现有栈用于短期验证，另选固定正式版本建立独立研究基线；升级应在独立环境比较后决定。

## 5. 路线建议

推荐分层混合方案：可测量传感器 → 状态估计／目标相对估计 → 学习策略 → 参考姿态／角速度控制器 → 有约束的电机模型。任务调度与安全监督独立于策略。

另外两条路线可作为对照：传统控制和规划更容易建立基线；直接从图像学习电机动作需要同时解决动力、感知、时延与安全，现阶段变量过多，不推荐作为首轮主线。

### 阶段顺序

1. 固定独立实验环境和版本；完成训练、保存、重载、评估短闭环。
2. 参数化机体、逐旋翼推力和反扭矩、响应滞后、饱和、电源变化及完整碰撞外廓；先验证参考控制器。
3. 首个学习任务：估计观测下的水平速度跟踪和定高悬停；零速度指令作为悬停子任务。
4. 起飞、短距离移动、降落；评估接地和近地动力模型局限。
5. 加入前向视觉、障碍与目标检测跟踪；由合成数据训练感知，导航策略使用相对目标和可通行空间。
6. 下视标记捕获、平台相对定位和末段降落；标记不可见、观测失效时执行独立安全逻辑。
7. 起飞—侦察—返库—降落—卸载—模拟充电—下一轮；先用事件式能源与机库模型，再替换实测参数。
8. 模型导出、推理预算与硬件测量计划；树莓派部署、飞控接入和实飞另行决定。

### 首个任务定义（建议）

- actor：估计的机体系速度、重力方向、角速度、测距高度误差、目标速度、上一动作及观测有效性／年龄。IMU和光流不能直接视为真实速度或位置；必须体现融合、测距有效条件、时延与失效。
- action：受限横滚／俯仰目标、偏航角速度及总推力请求，经过参考内环、混控和逐电机限幅。最终飞控是否支持该组合及推力标定仍 TBD；仿真接口不等于硬件接口已完成。
- critic／reward／evaluation：允许使用真值；actor 不使用真值位置、无噪声速度或障碍真值。
- reward：速度误差、高度误差、姿态倾斜、动作变化与持续饱和；碰撞、越界和观测失效用独立判据。
- termination：机体接触障碍、越界、失控、观测失效超过允许时长；时间上限为截断。门限均配置化。
- baseline：相同模型和观测下的传统速度／定高控制；学习策略必须比较抗扰、误差与饱和，不能只展示能飞。
- PROPOSED 验收：连续悬停10s，水平漂移<=0.15m、高度误差<=0.08m、完整机体无碰撞；独立测试至少200回合，成功率>=95%，报告分母、失败类别和至少3个训练种子。并非赛事规定。

水平漂移可用真值评估，但不向 actor 提供真实位置。若漂移不能满足门限，需要加强可部署的相对定位或视觉观测，不能靠新增世界真值输入解决。

### 本机资源安排（PROPOSED）

无图像动力学任务从64／256并行环境开始，根据显存、吞吐和步进稳定性扩容；视觉任务从8／16环境与较低分辨率开始测量。以上不是实测吞吐能力。32GB RAM处于基础要求附近，16GB显存限制多相机大规模训练；64GB RAM可作为后续扩展选择。

独立项目目录建议 `E:\isaac\proj_boom_birds`，独立版本锁定、模型参数、任务、评估集和实验日志；不直接修改官方四旋翼示例或旧 Reach 项目。

完整比赛约束任务应单独核算30s预算，其中至少10s用于悬停，还须容纳起飞、移动、返库和降落。当前几何未知，不能宣称完整循环一定能在30s内完成。数据卸载和模拟充电作为落地后的事件记录。规则仍是资料包快照，本轮没有核验赛事后续规则。
