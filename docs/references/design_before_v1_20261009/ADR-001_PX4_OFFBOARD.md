# ADR-001：保留PX4，首版选择速度与偏航角速度接口

日期：2026-10-09。用户明确底层保留PX4，并授权选择上位机接口。状态：架构选择已记录，接口实现／SITL／实板验收均NOT RUN；数值预算为PROPOSED。

## 决策

上位机负责感知、相对定位、任务、传统或学习制导，输出`[vx, vy, vz, yaw_rate]`。PX4负责速度、姿态、角速度控制、电机分配与其自身模式／失联逻辑。位置指令作为定位有效后的辅助技能接口。姿态／推力和逐电机输出仅保留为未来独立研究分支，不进入首版策略链。

| 接口 | 保留的控制能力 | 本项目选择 |
| --- | --- | --- |
| 位置 | PX4位置及下层控制 | 定位可靠后用于航点、定点等技能 |
| 速度＋偏航率 | PX4速度及下层控制；上位机决定运动 | 首版主接口，便于避障、跟踪、进近 |
| 姿态／角速度＋推力 | 仅保留相应下层环节 | 需要承担更多稳定性与动力误差验证 |
| 总力／力矩或电机输出 | 绕过相应内部控制环；电机直控不再获得常规姿态闭环修正 | 不满足首版保留底层控制的设计目的 |

PX4的速度控制仍需有效速度估计，位置控制需有效位置估计；选速度接口不会免除定位、传感器或失效验证。文档依据为[PX4 Offboard说明](https://docs.px4.io/main/en/flight_modes/offboard)。具体支持以最终锁定固件为准，main文档不视为本机实板版本。

## 协议、坐标与权限

主传输采用MAVLink；首选显式的`SET_POSITION_TARGET_LOCAL_NED`适配器，启用三轴速度和yaw_rate，屏蔽位置、加速度和yaw字段。字段掩码、坐标、固件支持与模式行为必须在SITL逐项测试，不发送混合语义命令。

项目内部使用本地ENU速度和逆时针为正的偏航率；适配器执行`v_NED=[v_ENU.y,v_ENU.x,-v_ENU.z]`和偏航率符号转换。两端的本地原点与轴方向必须已对齐；估计器重定位／坐标重置时重新校验目标和坐标变换。机体系目标先用估计姿态或声明的航向旋转转换，不混用完整机体系与水平航向坐标。

位置模式是显式技能切换，必须通过仲裁、估计有效性与模式确认。学习器不解锁、不切模式、不设置飞控参数；仅产生有期限的速度命令。单一Offboard网关负责发送、遥测和状态确认。

MAVSDK可作为网关替代实现，但NED速度＋yaw角接口不能误当速度＋yaw_rate。它的自动重发行为也必须纳入看门狗设计。[MAVSDK Offboard指南](https://mavsdk.mavlink.io/main/en/cpp/guide/offboard.html)。

## 频率与失效边界

PROPOSED策略20Hz、网关50Hz，命令有效期150ms；这些需要闭环延迟与稳定性测试。网关重发只能保持原命令有效期，不能把旧策略输出伪装成新决策。

必须分别测试：策略卡死但网关活着；网关退出；通信丢包；遥测过期；速度估计失效；Offboard进入被拒绝；任务控制切换未确认。策略过期时由网关按已验证的状态依赖策略回退，并验证PX4确实切换；网关／链路消失时由PX4自己的Offboard-loss逻辑处理。不能一边无限重发旧指令一边期待PX4检测到上位机失效。

配置`COM_OF_LOSS_T`和`COM_OBL_RC_ACT`等所需参数时应考虑当前估计能力和可用模式，不能把任何室内无GPS情况都设成自动返航或悬停。独立停桨链路另测。PX4 failsafe是经配置和验证的保护机制，不是对所有错误动作的保证。

## 训练与验证后端

- F0：Isaac Lab向量化动力学＋受限飞控代理，用于训练。保留速度响应、延迟、倾角、推力和饱和限制，不瞬间设置刚体速度。
- F1：真实PX4 SITL闭环，用于校准、固定评估、模式与故障验证。SITL让飞控软件实际运行，但仍是仿真证据。[官方SITL说明](https://docs.px4.io/main/en/simulation/)。
- M1先验证独立SITL和速度接口；M3接入Isaac传感器／执行器桥。Windows宿主的SITL可评估独立WSL2／Linux后端，其可用性、网络和锁步能力尚未检查。桥不可用时必须报告BLOCKED，不能把F0改名为PX4。
- 观测Oracle／E0／E1与控制F0／F1是两个独立维度。移植前必须通过E1＋F1；跨后端性能下降进入差异报告。

## 对原设计的修订

旧版“策略输出姿态和总推力、学习速度跟踪外环”不再是主线。速度跟踪和悬停改为PX4基线。首学习任务为相对目标到达与保持，使用四维速度动作；观测和动作schema升级，旧任务定义不能复用checkpoint。

新增`lab/autopilot`、`lab/bridges/px4_sitl`、`runtime/adapters/px4`、`configs/autopilot`和`env/px4-toolchain.json`的目录规划。原交接资料及此前环境报告保持历史快照，不重写其结论。
