## 3. 第一轮实施顺序

1. 导出现有包版本、源码提交和依赖冲突，记录文件与资产来源。
2. 建独立Isaac Lab工作副本与独立venv，处理已知依赖冲突；不复制venv目录。
3. 将启动、关闭、GPU步进、官方任务训练与重载接成最短可重复验证。
4. 建核心坐标／契约测试、参数登记表和模型v0；校验单电机力矩及推力分配。
5. 先建立PX4 SITL的速度／悬停基线，核验模式和失联行为；再校准F0代理的带宽、限幅与延迟。SITL后端宿主和固定版本在M0／M1中选定。
6. 注册相对目标到达与保持任务，输出速度＋偏航率，从小并行规模开始训练。
7. 与传统相对目标制导器做同条件比较；M3在真实PX4 SITL闭环复核，不能用代理训练成功替代。

后续视觉、能源和完整任务模块无需在这一轮全部实现。

## 4. 评估制度

- 种子：训练建议11、23、47；验证和最终测试使用独立种子范围。模型选择只使用验证集。
- 首任务：每个训练种子分别运行至少200个固定测试回合；汇总全部结果，同时保留每个种子的结果和分母，不只展示最好模型。
- 参考控制器使用同一场景／初态／扰动集合。记录均值、P95、极值、失败原因、终止原因和成功率区间。
- 有效尝试分母预先定义：进入任务初始化的所有尝试均记录。策略崩溃或超时不能被静默丢弃；基础设施失败单列，并同时公布计划数、启动数、有效仿真数和完成数。
- 训练／测试隔离包括场景、纹理、目标实例和动力参数集合，不能仅更换随机种子。
- 困难样例独立成回归集，不能用它替换保留测试集；用于调参后该样例即不再是未知测试数据。
- 每次报告标明模型检查、软件、仿真、机载推理、台架或实飞；不同证据层级分别统计。

## 5. 模式与任务预算

`research` 模式允许较长episode用于学习；`competition_snapshot_20260909`模式应用资料快照约束。两者报告分开。

完整任务飞行预算：起飞＋到观察点＋至少10s有效悬停＋返库＋对准／降落＋安全余量<=30s。机库几何与场地路径确定后再分配各段预算。超时计时的研究定义固定为起飞状态开始至确认接地，并明确区别于尚未确认的官方计时口径。

卸载与充电在接地后计入循环总时间，不能用它们重置仍在空中的飞行计时。能源不足触发提前返库时，记录任务未完成与成功安全收尾两个独立指标。

## 6. 退出与恢复原则

同一阶段失败时保留日志／配置／模型，冻结可复现失败样例后定位最早异常。训练停止的异常checkpoint不得晋升为候选模型。环境升级、动力参数大幅变化、观测契约变化都要求重跑受影响阶段的回归，而不是沿用旧PASS。
