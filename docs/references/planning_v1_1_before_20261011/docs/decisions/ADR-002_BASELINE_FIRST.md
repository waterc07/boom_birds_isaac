# ADR-002：先建立传统闭环，以证据决定学习模块

日期：2026-10-09。状态：本轮规划采用；实现和任务验收 NOT RUN。

## 决策与优先级

用户要求保留 PX4，尽可能降低学习与试错成本，并继续规划。结合成熟方案调研，首阶段采用传统感知/几何定位、传统有界速度控制及真实 PX4 SITL；学习模块由基线失败证据决定是否需要及负责哪一层。

本记录覆盖旧design/01–06与旧ADR-001中首阶段PPO、27维观测、F0代理训练和先建设联仿的安排。当前六份设计与ADR-001已同步为v1.1；旧文件归档references/design_before_v1_20261009。保留PX4底层、速度＋偏航率、单一发送端、坐标单位和命令过期原则；接口实测仍NOT RUN。

## 当前采用与延后决策

- 采用：需求/质量/供电预算前置；仿真接口验证可以先于完整硬件参数闭合。
- 采用：Windows 继续承担现有 Isaac 和资料工作；PX4 SITL 规划使用 WSL2 Ubuntu 24.04。两套环境独立。
- 采用：先做 PX4 无视觉接口验证，再做目标相对接近与保持；仿真真值只用于明确标注的接口实验和评价。
- 条件采用：允许标记且任务适用时，标记定位为首个感知基线；不宣称赛事允许。
- 延后：具体检测网络、VIO/SLAM、PPO、Pegasus、Isaac↔PX4 运行时桥接和完整赛事场景。
- 未确定：最终机载计算平台是否必须为 Pi 5、精确实板固件、目标和返库定位方案、正式任务数值门限。

## 后果和变更条件

保留已有 Isaac 安装，现阶段不为其复制环境或运行短 PPO 训练。首个技术交付变为可复现的 PX4 速度接口与故障验证记录。默认仿真机体只证明集成链路，不能证明 120 mm 微型实机性能。

只有观测可获得、全链预算可行且基线存在明确能力缺口时才引入学习。若目标不可持续观测或返库漂移无法闭合，先补导航能力；若质量/能源不满足任务，先调整硬件，不通过换算法掩盖约束。
