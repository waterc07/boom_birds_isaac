# S0：软件合同与PX4最小基线执行计划

v1.1，2026-10-10。本计划SITL/速度接口/故障测试尚未执行。用户已完成PX4 1.17无GPS、光流、无磁力计定高与MAVLink通信验证；先登记复用该基础，不重复证明能定高。当前目标仅交付此计划，不实施安装或业务代码。[总纲](../../PROJECT_PLAN.md)及[架构](02_ARCHITECTURE.md)是规格。

## 为什么先做这个

先证明一条真实PX4速度＋偏航率链路和失效语义。无需真实目标、Pi最终选择或完整微型机动力，能最早发现坐标/模式/TTL/工具链错误。理想定位仿真成功不支持无GPS、视觉或实机结论。

首阶段结果包括W01合同、W02工具链与SITL报告；已有预算程序是规划工具，不是这个运行器。

## 执行顺序和每步出口

1. W01只用标准库实现合同，离线验证：ENU正/负三轴、yaw_rate、往返变换；mask1479；非有限/超限输入；150ms到期；乱序seq；epoch重置；重发不续期；模式ACK但未确认不能ACTIVE；缺估计标志不算有效。成功=全部预期断言通过且失败理由可查。失败停在合同层，不安装仿真扩展。
2. W02在后续实施授权下准备一套WSL及PX4，锁候选提交/工具。以该提交官方Ubuntu脚本为依据，审查必要参数再执行；记录工具版本/依赖检查。默认完整官方依赖路径优先可复现，不自行删依赖猜“最小”。成功=依赖检查/构建PASS，失败记录最早错误而非重复全装。
3. 在PX4源码根运行官方命令 `make px4_sitl sihsim_quadx`（仅已完成工具链时）。[版本文档](https://docs.px4.io/v1.17/en/sim_sih/)确认此目标，不需要FC、相机或GUI。保存终端、PX4参数/ULog位置。启动3次并正常退出3次后判环境PASS；SIH不适用确认后转同版本官方Gazebo，不先建Isaac桥。
4. 核实MAVLink实例/UDP端口与sysid/compid，获取心跳、姿态、局部状态、质量/模式；不能假定端口或ESTIMATOR_STATUS默认流。按固件能力请求消息频率并记录支持/ACK/实际到达频率。只有协议握手及有效状态已确认才预流；无消息先查Linux端口/实例日志，再查协议，避免混入Windows网络故障。
5. 试验先用SIH默认理想定位，启用仿真标识；预流1.5s后请求Offboard及仿真解锁，HEARTBEAT实际模式确认后ACTIVE；拒绝/超时立即失败。不开真实串口，不向真实板解锁。候选测试空间平坦无障碍，定高1m、速度幅值0.5m/s、yaw_rate幅值0.3rad/s；先逐轴2s+恢复，再组合，不使用真实地形/目标。
6. 测连续保持10s（控制基线，不等于制作规范验收）；软件合同全通过后每种正常用例5次、独立重启3次。候选稳定后水平位置误差≤0.2m、垂直≤0.1m、速度跟踪误差P95≤0.15m/s；稳定窗口与期望参考由运行器记录。数值为PROPOSED，仅判此默认模型，不代表微型实机。坐标方向、模式、有限值及TTL为强制合同；跟踪失败定位模型/参数，不调整指标隐藏失败。
7. 执行下表故障矩阵，每例至少3次；保存事件到处置时间、模式确认、PX4日志。任何旧非零命令续发、模式未确认却ACTIVE、无效估计继续任务均FAIL。真实重置/估计失效注入不能完成时标NOT RUN，不以离线注入冒充真实飞控故障通过。
8. 汇总正常与异常分母，锁环境/参数/源码/哈希；退出SITL与本run网关，确认所记录PID/端口释放，不批量杀其他python/Kit/PX4。不删除失败日志。阶段PASS仅在必测矩阵完成；未覆盖真实状态故障可交付部分基线，但S0阶段保持部分完成。

## 故障矩阵

| 故障输入 | 应观察的处理与验收 | 覆盖层 |
| --- | --- | --- |
| 策略停更，网关仍活 | 到期后最多一个发送周期内不再发旧非零指令；进入RECOVERY并按已验证条件确认安全模式/终止流 | 离线＋SITL |
| 网关退出/UDP中断 | 不再生存流；按锁定COM_OF_LOSS_T及飞控机制进入配置回退，时序和最终模式有证据 | SITL |
| 旧seq/旧epoch/非法数值 | 拒绝并记录，不发运动命令；epoch改变重算导航目标/原点 | 离线；实遥测重置单列 |
| 遥测过期/质量无效 | UNKNOWN/invalid阻断任务，不把零速等同可悬停；执行已验证回退 | 离线＋SITL可注入部分 |
| 模式进入拒绝/退出拒绝 | ACK和实际模式都记录；不进入ACTIVE，退出超时不无限续旧流 | SITL |
| 超延迟/旧图像 | 观测年龄与命令期限分别拒绝；跨时钟未同步不推算年龄 | 离线，S1真实采集补验 |
| 初始朝向偏置/坐标重置 | 识别epoch/方向不一致并暂停正常任务；真值不偷偷校正部署估计 | 离线＋后续无GPS |

回退数值须在SITL先锁定：例如失联阈值/回退确认时间不是现在已测参数。不得用“收到Land ACK”替代飞控实际模式/接地确认；有位置估计的理想Hold结果不得迁移无GPS。

S0开发初值PROPOSED：心跳接收龄≤2s、姿态/局部状态/质量接收龄≤200ms、模式请求确认超时2s、COM_OF_LOSS_T候选0.5s。按实际消息率/调度/固件校准并冻结配置，不能因低速心跳满足而忽略状态过期。失联试验观察到的回退延迟对比阈值＋记录的通信/调度界；最终模式以实际HEARTBEAT/ULog确认。无法用原生消息覆盖质量/重置时明确补充源或保留阶段部分完成，不默认为有效。

## 日志和失败定位

run.json至少包含host/OS、源码/固件/子模块SHA、参数和锁/标定哈希、时钟来源、GPS/真值标识、试验case/重复编号、起止、result/reason。命令日志含原始seq/issued/expires、转换前后值、重发时间；遥测含PX4时间/接收时间、mode/armed/quality/reset；指标含分母、P95/极值、恢复事件、原始日志索引。

定位顺序：构建/依赖→进程和端口→协议收发与mask→状态质量/时间→预流/模式→控制响应→监督故障。每层最早异常保留可复现输入；新版本只重跑相关基线，版本/坐标合同变化不得沿用旧PASS。

首阶段放行G0=环境锁与W01/W02必测结果齐；不代表G1视觉或G3实机。下一步是W03真实视觉与W04完整BOM/局部状态输入，两条独立收证据，不立即启动PPO。
